# DemoE · Е-Шлюз

PWA-демо обмена документами: несколько получателей, маршрутизация, проверки, карантин, ответное подписание и ZIP-пакет. Без интеграции с 1С.

[Открыть приложение](https://foxyevilmp.github.io/DemoE/)

## Как пользоваться

1. Откройте приложение и нажмите «Открыть локальное демо». Для настоящего обмена после подключения сервера войдите по ссылке из письма на свой email.
2. Нажмите «Новый документ», укажите до 10 получателей и загрузите PDF, DOCX или XML до 10 МБ. Можно выбрать демо-шаблон.
3. Заполните реквизиты и нажмите «Подписать и отправить». Демо-PIN: `12345678`.
4. Получатель открывает документ во «Входящих», подписывает в ответ или отказывается с указанием причины. В локальном демо переключайте участников в верхней полосе.
5. В карточке доступны статусы адресатов, история, SHA-256, оригинал и ZIP-пакет. Для показа ошибки выберите карантин при отправке, для маршрута через демо-СБИС — УПД.

Установка: меню браузера → «Установить приложение». На iPhone: Safari → «Поделиться» → «На экран Домой».

## Статус и настройка

Исходники опубликованы. Сборка и тесты пройдены в GitHub Actions. Пока Supabase и SMTP не подключены, доступно локальное демо без настоящих писем и обмена между устройствами. Для онлайн-обмена нужен интернет; адреса пользователей могут принадлежать любым почтовым сервисам. Отправка поддерживает Mail.ru SMTP. [Инструкция подключения](docs/SETUP.md).

КЭП, ГОСТ, TSP, PKI и внешние операторы имитируются. `.sig` — демо-запись, а не юридически значимая подпись. Файлы и SHA-256 настоящие.

## ПЭП по Email/SMS OTP · v1.1-PEP

На входе выберите тестового отправителя/получателя либо введите произвольный email или телефон в международном формате и ФИО/организацию. Чекбокс соглашения предварительно отмечен только для ускорения демо. «Читать оферту» открывает полную редакцию v1.1-PEP. После «Получить код и войти» в баннере появится случайный четырёхзначный код; его подтверждение сохраняет профиль ПЭП и акцепт в localStorage, выбранный профиль — в sessionStorage.

В «Новый документ» подставьте шаблон, задайте другого получателя и нажмите «Подписать и отправить». Выберите «ПЭП по одноразовому коду», запросите отдельный код и подтвердите подписание. Для ответной подписи смените профиль через баннер, войдите по коду от имени получателя и откройте входящий документ. Телефон получателя в локальном режиме задаётся без пробелов: +79991234567.

Код подписания связан с идентификатором и SHA-256 файла, действует 5 минут, допускает 5 попыток, используется однократно; новый код отменяет прежний. OTP не сохраняется в профиле или архиве. Квитанции, manifest.json, protocol.html и signatures/pep-N.json содержат подписанта, канал, время, хэш и реквизиты акцепта. Для УПД с НДС ПЭП заблокирована, сохранена имитация КЭП.

Это локальный демонстрационный сценарий: Email/SMS не отправляются, владение контактом не проверяется, данные браузера не являются независимым доказательством. Существующий онлайн-обмен Supabase и имитация КЭП сохранены отдельно; открытый демо-код не предоставляет доступ к онлайн-документам. Для реального применения ПЭП нужны серверный OTP, надёжная идентификация/журнал и действующее соглашение участников.

Проверки: npm test (включая срок OTP, лимит попыток, повторное использование, изоляцию профилей, подмену файла, двустороннее подписание и экспорт), npm run build.

## Реальные Email-коды · v1.2-PEP

На экране входа основной режим — «Email-код · онлайн». Код из 6 цифр доставляется на почту через действующий SMTP Mail.ru; в браузере он не отображается. Подтверждение выдаёт сессию Supabase и фиксирует профиль и редакцию соглашения в pep_profiles. Старый вход по ссылке и локальное демо сохранены отдельно. SMS не подключены.

Для договоров и актов выберите ПЭП в окне подписания. Сервер отправит отдельное письмо с названием файла и SHA-256; подтверждение одновременно погашает код и создаёт документ либо ответную подпись. Повтор того же подтверждения возвращает результат без повторного документа. КЭП/ГОСТ и УПД по-прежнему демонстрационные.

Backend: supabase/functions/pep-email. Переменные SMTP_USERNAME, SMTP_PASSWORD, SMTP_HOSTNAME (по умолчанию smtp.mail.ru), SMTP_PORT (465), MAIL_FROM и APP_URL берутся из секретов Edge Functions. Серверный ключ Supabase используется только внутри backend. Открытый OTP не хранится; HMAC привязан к случайному challengeId. До 5 попыток, срок 5 минут, повтор отправки через 60 секунд; ограничения 5 запросов/email/час, 20/IP/час, 100/проект/час. Новый запрос отменяет предыдущие коды для контакта.

pep_challenges закрыта для anon/authenticated; pep_profiles доступна пользователю только для чтения своего профиля. Подтверждающие RPC доступны исключительно service_role. Не выдавайте эти права браузеру.

Контрольная SMTP-отправка выполнена 14.11.2026; провайдер принял письмо. Попадание во «Входящие» зависит от почтового сервиса. Подтверждение email само по себе не удостоверяет личность и полномочия представителя; применимость ПЭП определяется соглашением и видом документа.
